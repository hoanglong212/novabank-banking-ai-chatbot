# QR Pay redesign

User requirement: opening QR Pay shows scanning first, then exactly three primary actions in this order: Mã QR của tôi, Chuyển tiền bằng hình ảnh, Tải ảnh lên. Preserve the violet/light visual direction and existing transfer review/OTP protections.

## Direction

Considered (1) an immersive dark full-page camera, (2) a light workspace with a central camera viewport and three actions underneath, and (3) a split receive/scan dashboard. Choose (2): it makes scanning the first task, retains the existing app palette, scales to mobile, and avoids competing receive forms. (1) would disrupt the established light app; (3) repeats the current competing-form problem.

Use an ivory canvas, large restrained heading, dark camera viewport with violet corner guides, a quiet instruction line, and three clearly labeled actions. Animate scanner/status changes softly, with reduced-motion support. Receive details open in the existing accessible Sheet. Upload keeps the original validated NovaBank PNG flow. Image-transfer semantics are being clarified with the user.

## Implementation and checks

1. Add a reusable camera scanner with explicit camera activation, capability detection, actionable errors and stream cleanup when hidden/unmounted. Browser-native QR decoding is progressive enhancement; Windows may require a separately approved QR dependency. No silent installation.
2. Reorganize QrStudio with the requested order; preserve receive/download/text decode and decoded-recipient review. Stop camera before opening other modes. Keep data out of the assistant and never transfer automatically.
3. Exercise default order, modal keyboard behavior, upload/read/review, unsupported or denied camera, cleanup, mobile overflow and reduced motion. Update the existing QR acceptance test for the new layout.
4. Run build, component checks and relevant real-backend E2E; inspect rendered desktop/tablet/mobile screenshots. Report camera/reader limitations honestly. No unrelated backend, auth, theme or banking-rule changes.

The initial plan did not authorize dependencies. On 2026-11-08 the user explicitly approved jsqr 1.4.0, tesseract.js 7.0.0 and local English/Vietnamese language data to complete both readers. Image transfer means OCR of bank/account text; QR upload is a separate action. Prior working-tree changes remain intact. The existing frontend API proxy fix to port 8080 must be preserved.
